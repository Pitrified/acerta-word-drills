# acerta - bootstrap

## The idea

A phone app for the vocabulary drills that today exist only in the lang-tutor web app.
It is separate from fala (the chat tutor) for now; the two may merge later.
The name is a working one: *acerta* is "get it right", a short pt imperative like *fala*.

The content is the lang-tools lexicon.
The app is written fresh in this repo, the way fala was written from flutter-setup-project:
this plan is the instruction, and fala-language-tutor and flutter-setup-project are the reading
material for tooling and conventions.

## What was found (2026-11-14)

Three read-only surveys, of flutter-setup-project, fala-language-tutor, and the lang-tutor and
lang-tools servers.

- **No template script.** flutter-setup-project has no instantiate or rename step.
  Its recorded way is a session pointed at an empty repo with a plan.
  fala was made so, from a `git archive` of the template with the on-device model removed.
- **fala shares tooling, not product.** It is a chat tutor that calls OpenAI from the phone.
  It reads nothing from lang-tools or lang-tutor.
  What carries over: `scripts/check.sh` and its gates, `scripts/plans.py`, the git hook, the CI
  workflow, `analysis_options.yaml`, the docs layout, the instruction file, the Android
  scaffold, the build and release notes, and the e2e harness on the `fala_api36` emulator.
- **lang-tutor cannot serve a phone as it stands.** Login is a Google web cookie, progress is
  held in memory and lost on a restart, and it is deployed nowhere.
  Its pair matching logic is small and self-contained: `exercises/pair_matching.py` (204 lines)
  and `progress/selection.py` (221 lines).
- **The words for pair matching are few enough to ship.** Counted on the corpus built on
  2026-11-13, with the web drill's own filter (pt, single word, 3 letters or more, has an English
  translation, no function words, no inflected forms):

  | Level cap | Words |
  | --- | ---: |
  | A1 | 330 |
  | A2 | 847 |
  | B1 | 1,893 |
  | B2 | 2,858 |
  | C1 | 4,066 |
  | C2 (everything) | 29,376 |

  Up to B1, 207 of the words are a false friend of an English or Italian word and 856 have a
  cognate.
  A card is about 600 bytes as the read API sends it; trimmed to what the drill shows, the
  whole 29,376 should be a few megabytes before compression (to be measured in phase 2).
- **The data license asks for a visible credit.** lang-tools' `DATA_LICENSE.md` (CC BY 4.0)
  gives the text to show on an about screen, and asks that the WordNet 3.0 notice travel with
  any copy of the data. French (WOLF, CeCILL-C) is outside that grant; this app ships no French.

## Decisions

Functional ones are the answers below. The technical ones, taken without asking:

- **Android only**, min API 26, as fala. Application id `com.acerta.app`, package name `acerta`.
- **Same stack as fala**: Riverpod, go_router, Hive, freezed and json_serializable.
  None of fala's product dependencies (OpenAI client, speech, secure storage).
- **No network at all.** The release manifest asks for no internet permission.
  That keeps the privacy statement to one sentence.
- **The words are a bundled asset**, generated by a Python tool in this repo that reads the
  lang-tools corpus through its public in-process API, run from lang-tools' environment.
  lang-tools is not changed and does not learn about this app.
  The asset records the lang-tools version and the corpus build date it came from.
  Rejected: calling the read API from the phone (needs hosting, and a connection);
  an export feature inside lang-tools (no second consumer yet; revisit with lang-tools'
  distribution plan).
- **The drill logic is rewritten in Dart** from lang-tutor's pair matching and word selection,
  keeping their behaviour and their numbers, with tests that mirror lang-tutor's.
  Rejected: sharing code with lang-tutor (different language, and no server).
- **Progress is keyed by the lang-tools lemma id.** Those ids are deterministic, so a content
  update keeps progress as long as the ids hold.
- **Flutter is pinned to the version installed on the build box** (3.47.7), in CI too, so the
  local check and CI agree. fala and the template pin 3.44.5.
- **All 29,376 words ship**, and the level cap is a filter in the app, unless the measured
  size says otherwise.
- **Subagents do the bulk writing** on smaller models, one bounded task each, with the plan
  file as their brief; the orchestrating session reviews every diff and runs the gates.

## Behaviour carried over from the web drill

- A round shows pt words on the left and their translations, shuffled, on the right, in
  English or Italian by a setting (Q10).
- The learner taps a left word, then a right word. A right pair locks; a wrong one counts an
  error against the left word and can be tried again.
- When two words of a round would show the same English word, the second takes its next
  translation, or is replaced by a spare.
- At most one false-friend decoy joins the right column: a word of the right-hand language
  that looks like one of the pt words and does not mean it. Tapping it for its look-alike shows
  the trap note.
- Words are drawn at random, weighted: unseen words five times, a missed word more with every
  error, easier levels slightly more, false friends slightly more, cognates slightly less, and
  a word seen within the last hour less.

## Open questions

- Q1: Which drills go in the first version?
  - ANS: pair matching only.
- Q2: Should the app work on its own, or through a server?
  - Recommended: on its own, offline.
  - ANS: on its own, offline.
- Q3: Which languages does the first version cover?
  - Recommended: Portuguese, for en + it speakers.
  - ANS: Portuguese, for en + it speakers.
- Q4: A working name?
  - ANS: acerta.
- Q5: How does the learner choose the difficulty?
  - a. A level setting, A1 to C2, B1 to start with, as the web drill has. It caps the words
    drawn (the table above).
  - b. Fixed at B1 for the first version.
  - Recommended: a, because 1,893 words is a narrow pool for a learner past B1, and the cap is
    one filter.
  - ANS: a.
- Q6: How many pairs in a round?
  - a. Fixed at 5.
  - b. A setting, 3 to 8, 5 to start with.
  - Recommended: b, because the right number depends on the screen and on taste, and it is one
    number.
  - ANS: b.
- Q7: What does the learner see when a round ends?
  - a. A summary of the round: each pair, the word's meaning (the English gloss), its level,
    its look-alike notes (the false friend or cognate in English and Italian), the missed
    words marked, then "next round".
  - b. Straight into the next round.
  - Recommended: a, because it is the only place the meaning and the look-alike notes get read;
    during the round there is only the decoy.
  - ANS: a.
- Q8: Is there a progress screen?
  - a. A small one: words seen out of the total per level, and the words missed most.
  - b. None in the first version; progress only steers which words come up.
  - Recommended: a, because on-device progress that the learner cannot see reads as none.
  - ANS: a.
- Q9: Can the learner hide a word?
  - a. Yes: "don't show again" on the round summary, and a list of hidden words in settings
    to bring one back. The corpus has junk and rare words, and lang-tutor's selection already
    has this flag with no way to set it.
  - b. No.
  - Recommended: a. It needs the summary of Q7.
  - ANS: a.
- Q10: What is on the right-hand side?
  - a. English only. Italian shows up in the look-alike notes.
  - b. A setting: English or Italian translations.
  - Recommended: a, because the Italian side has had no review as a translation column, and the
    decoys and trap notes are written against English first.
  - ANS: b, English or Italian. Folded in: the asset carries both translations, the round
    builder takes the side's language, and the decoy comes from that language's false friends.
    Counted on the same corpus, the words with an Italian translation are 321 (A1), 821 (A2),
    1,805 (B1), 2,655 (B2), 3,638 (C1) and 19,240 in all; up to B1, 41 of them have a full false
    friend in Italian to draw a decoy from, against 55 in English.
    The summary's meaning stays the English gloss on either side.
- Q11: How far does the first version go in distribution?
  - a. Onto your phone only (a signed APK file you install), with the GitHub repo public like
    fala's. A GitHub release is a follow-up folder.
  - b. A GitHub release of the APK as part of this bootstrap, as fala has.
  - Recommended: a, because a release needs a keystore and a first round of use on the phone
    will change things.
  - ANS: a.
